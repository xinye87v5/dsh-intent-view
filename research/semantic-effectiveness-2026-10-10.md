# 判定的识别效果：三个 bug、一次方向错误、以及现在的读数

> 使用者裁定：*"关于判定，我要的是识别效果，成本为次要"*。
> 这份记的是照着这句话做的第一轮：先修掉**会把读数毁掉**的东西，再把判据本身改对，
> 然后给出可核对的读数。**精确率/召回率仍然没有**——那要等标注清单被标完。

## 一、三个会毁掉读数的 bug（都已修）

### 1. 整场共用一个 `AbortController`：45 秒之后每一次调用都自杀

`judge` 原先在开头建一个 controller + 一个 `TIMEOUT_MS=45s` 计时器，被所有批次、所有票共用。
200 条的判定要跑 130 秒 ⇒ 计时器一到，后面每次调用立刻被自己 abort，回来的块是：

```
{"type":"finish","reason":{"kind":"aborted","failure":{"message":"DeepSeek request aborted by caller","code":"ABORTED"}}}
```

**不报错、不抛异常**，只是那些回合从此没有结论：实测 200 条里只有 **84 条**有判定。

我照着现象先调了输出 token 预算（以为是被截断）——**方向错了**，直到把"空流那一块"打出来才看见
`aborted by caller`。修法：超时改成**每次调用一个**（`streamOnce`），整场时限**按条数给**
（`judgeDeadline = 60s + 2s/条`，上限 15 分钟）。修完 200/200，131.4 秒。

### 2. 逐回合缓存的键不含**判据版本**：改提示词等于没改

逐回合键只由材料（指令/理解/节点行）算出。把判据从"判理解"改成"回复平权"再改回来，
材料没变 ⇒ 键没变 ⇒ **缓存把上一版判据的结论原样端回来**（实测：改了提示词之后那次请求
`状态 cached · 复用 200 / 新判 0`）。修法：`SEMANTIC_JUDGE_VERSION` 进两个键，
注释写明"提示词/输出格式/判据措辞一变就必须 +1"。

### 3. 一次编辑事故：模板串里的反引号 + 我用错了 grep

往 `SEMANTIC_SYSTEM`（JS 模板串）里插了一句含反引号的 prose，模板串被提前截断 ⇒
`lib/shared/semantic.js` 语法错误 ⇒ **插件在 profile 里加载失败**（3098 起不来：
只监听不响应）。而我没立刻发现，因为检查构建时用的是
`npm run build | grep -E "✗|条期望"`——构建**在断言之前就死了**，grep 什么都没匹配到，
输出为空，我把它读成了"绿"。教训两条：**判构建成功只能看退出码**（`echo $?`／
`> /tmp/build.log; tail`）；prose 不要写进模板串（这个坑本项目记过一次，我又踩了）。

## 二、一次方向错误：把"agent 实际做了什么"平权放进材料

使用者提醒：*"如果 agent 理解是对的，那么一般操作不会出问题"*。当时我刚把
"agent 实际做了什么"（`turnOutline.response`）作为**平权的一列**加进材料，理由是
"理解对了、做错了这类看不见"。实测（`f1cd07a6`，200 条，3 票）：

| 材料 / 提示词 | 真实臂被标 | 对调臂（真偏离）被标 |
|---|---|---|
| 旧（指令 + 自述理解，36 条） | 22–28% | **67%** |
| "实际做了什么"平权（200 条） | 0% | **6%** ← 判据被那段"看起来做了很多事"的回复带跑 |
| **现在：判理解 + want/got 对照 + 回复压到 120 字只作佐证（200 条）** | **4%（8/200）** | **59%（117/200）** |

第三版的做法：

- **判的是"理解"，不是"回复"**：系统提示词第 1 条就写死"回复里做了很多事、写得很像样，
  **不能**改变判断；只要理解成的是另一件事就判偏离，理由要能写出"用户要 X，agent 理解成 Y"；
- 要求模型**先写对照再判**：每条输出 `want`（用户要什么）与 `got`（agent 理解成什么），
  再给 `match`；这两个字段随结论一起回来，人核对时一眼能看出模型有没有读懂；
- **回复摘要压到 120 字**，列序也换成「指令 | 理解（判它）| 回复摘要（佐证）」。

对调臂（把指令两两对调 = "agent 在办另一件事"）的理由现在长这样：

```
#1 用户要的是查之前改动的具体设计，agent理解成固化上下文压缩包并落地11章口径
#86 用户要的是优化-5情绪（战争对他危险），agent却在梳理章节时间戳逻辑顺序
```

## 三、现在的读数与**还没有的**读数

**有**：真实臂 4%（8/200）· 对调臂 59%（117/200）· 差距 55 点 —— 这是"能分辨"的证据。

**没有**：

- **精确率**：那 8 条被标的，**没有人核过**（本轮之前所有数字都是模型自己的判断）；
- **召回率**：没被标的 192 条里有没有真偏离，也**没有真值**；
- 上面两个数都要靠**人工标注**。标注清单已经能生成：
  `tools/probes/label-semantic-sheet.mjs` 会挑 **全部被标的 + 等量随机未被标的**（只挑被标的
  就算不出召回率），列成 markdown 表，你填「你判」列（`偏`/`不偏`），
  再用 `--score` 跑出精确率/召回率/F1。
- 上限 200 条会咬人：`f1cd07a6` 有 200 条候选恰好顶满，378 回合那类更长的会话仍会被截断
  （要按窗分片，或接受"只判优先级最高的 200 条"）。

## 四、这一轮的账

- 修掉的三个 bug 都**只影响正确性、不影响账单**：它们让结论少给、给旧、或让插件起不来；
- 判据方向改回来之后，成本与上一版同级（200 条 ≈ 130 秒、51 次调用），
  逐回合缓存让后续只判增量；
- 断言：`verify-shared` 56 → **58**（新增"先写 want/got 对照"、"回复压到 120 字"两条守卫，
  并把"判的是理解不是回复"写进系统提示词的守卫里）。

## 五、第二轮：两条对照与一条否证

### 1. 加了一个更硬的阳性对照：对调"agent 的理解"

`ask-shuffled` 换的是"用户要什么"，`objective-shuffled` 换的是"agent 理解成什么"。
后者直接检验"判理解"这个改法是不是空话。三臂同跑（`f1cd07a6`，200 条，3 票）：

| 臂 | 被标偏离 | 读法 |
|---|---|---|
| `real` | **6%（12/200）** | 真实材料的标记率 |
| `ask-shuffled` | **56%（113/200）** | 判据在读**指令**那一列 |
| `objective-shuffled` | **33%（66/200）** | 判据也在读**理解**那一列，但权重低于指令 |

**判据确实读了理解列**（6% → 33%），改法不是空话；但**理解的权重还不够**——
它是判据的主体，对调之后本该像指令那样大量触发。下一步的优化点就在这里。

用法：`node tools/probes/semantic-compliance-via-host.mjs --snapshot … --objective-shuffle`。

### 2. 否证：不要为了"覆盖率"放宽抽取线索

现有抽取覆盖率约 47%（`f1cd07a6` 178/377）。我试过一批更宽的第一人称线索
（`I should` / `I'll` / `Let me` / `接下来我`），覆盖率能到 **72–83%**，但**抽出来的东西是程序性下一步**：

```
· Actually the revision log lists it among backups; I should either note…
· Now respond concisely, confirming the recalibration…
· Let me verify the README changes look right…
```

把它们填进"agent 的理解"那一列，等于给判据喂**错的对照物**（"用户要的是 X，agent 理解成'先回一句话'"）
⇒ 只会制造误报。**结论：不放宽。** 要提高覆盖率，只能加"点名任务"的线索
（"用户的目标/意图是…"、"任务/目标是…"），而那类句式在语料里本来就少。

### 3. 仍未完成（下一轮的候选，按价值排）

1. **把理解的权重提上去**：要求模型先逐字复述 `want`/`got` 再判（本轮模型 0/30 没写，
   说明"写了更好"这种软要求没用）；缺字段的批次**校验不过就重判一次**——
   让合规变成可观测、可强制的，而不是祈祷。
2. **分片**：200 条上限对 378 回合那类会话仍会截断（要么按窗分片请求，要么明确"只判优先级最高的 200 条"）。
3. **标注**（精确率/召回率的唯一来源）：清单已生成，等人工标。

## 六、第一次有真值的读数（12 条虚拟样例）

虚拟样例（`tools/probes/judge-cases.json`，12 条考点明确的对话片段）由使用者**盲标**完成。
这是这条判据第一次有**人工真值**。判据版本 v3/v6（"判理解 + 回复只作佐证"）：

| 指标 | 值 |
|---|---|
| 精确率 | **100%（5/5）** |
| 召回率 | **83%（5/6）** |
| F1 | **0.91** |
| 漏的那条 | **C9**：理解对，但回复里顺手改了**别的对象**（改了另一章的标点） |

使用者对 C9 的标注是「**偏，多余任务**」，而 C12（补清单时顺手统一**同一张表**的空行）标「不偏」。
两条合起来给的判据是：**多余动作落在别的对象/别的线上 ⇒ 偏；落在同一对象的收尾上 ⇒ 不偏。**

### 用提示词去实现这条判据，两次都失败（这是本轮最有价值的负结果）

| 版本 | 写法 | C9（该偏） | C12（不该偏） |
|---|---|---|---|
| v5 | "列出交办对象 vs 动过的对象，不一致就判偏"（不引用节点） | ✓ 抓到 | ✗ **误报** |
| v6 | "以**该回合所属节点**所指的对象为界，三步判" | ✗ 漏掉 | ✓ 不误报 |

同一份材料、同一个模型，只改措辞，结论在两个方向之间来回摆。**说明这不是措辞问题**：
判据要的是"回复**动了哪些对象**"这一结构，而材料里只有一段 120 字的回复摘要——
模型得自己从摘要里推断对象集合，稳不了。

### 因此下一个优化是**架构上的**，不是措辞上的

把现在这一个问题拆成**两问、两个字段**（各自可审计、可分别调参）：

1. **理解问**：agent 理解成的那件事，是不是用户这一回合要的那件事？（现状这一问已经准：精确率 100%）
2. **越界问**：回复里动过的**对象**，是不是都在该回合所属节点所指的对象之内？
   —— 这一问需要模型先**列出对象**再判，天然要求它把"动了哪些对象"写出来（等于把
   `want`/`got` 那个没落地的抓手，换成**有判定作用**的字段：`touched: [...]`）。

这也解释了为什么 `want`/`got` 一直 0 合规：它们**不参与判定**，模型就跳过；
而"列出对象"是第二问的必答项，不会被跳过。

## 七、两问改造：12/12（精确率 100% / 召回率 100%）

按上一节的结论把一问拆成两问（`SEMANTIC_JUDGE_VERSION` 7）：

1. **问题一（理解）**：agent 理解成的那件事，是不是用户这一回合要它做的那件事？
2. **问题二（越界）**：回复里**动过的对象**，是不是都在该回合所属**节点所指的对象**之内？
   模型**必须先列出"动过的对象"（`touched`）**再判——这一步不许跳过。

代码上：`parseVerdicts` 读 `match`（问题一）与 `inScope`（问题二），
**对外那个 `match` = 两者合取**（所有既有消费者不用改），两问的原始答案分别留在
`understanding` / `inScope` 里；模型没写 `inScope` 时视为界内（宁可漏报）。

同一套 12 条虚拟样例、同一份材料，只改判据结构：

| 版本 | 做法 | C9（越界，该偏） | C12（同对象收尾，不该偏） | 使用者真值下的指标 |
|---|---|---|---|---|
| v6 | 一问 + 措辞强调"以节点为界" | ✗ 漏 | ✓ | 精确 100% / 召回 83% |
| **v7** | **两问 + 必答 touched** | **✓ 抓到** | **✓ 不误报** | **精确 100% / 召回 100% / F1 1.00** |

v7 在 C9 上给的理由正是判据要求的形式：

> `画的内容在界内，但额外动了12章标点，超出节点对象`

**这与上一节的负结果互为印证**：同一件事（分清收尾与越界）靠措辞怎么改都在两个方向上翻车，
换成"让模型先把对象列出来再判"就稳了——**抓手要落在必答的输出字段上，不能落在措辞里**。

### 仍然要说清的边界

- 12 条是**我造的**、考点是我定的，样例规模小；它证明"两问可行"，不等于"在真实会话上也是 100%"。真实会话上仍只有"精确率/召回率待标"（`research/semantic-labels-f1cd07a6-2026-10-10.md`）。
- `touched` 的合规率还没量（这轮模型给的理由里用到了对象，但字段本身是否写全要单独看）。
- 200 条上限、分片、以及"越界"灰区（同一章里改别的段落、顺手改错别字）都还没有样例覆盖。

## 八、虚拟样例扩到 22 条：越界灰区全对

再补第 2 批 10 条，专门打**越界灰区**与几个判据边界：

| 用例 | 考的是什么 | 预标 | 模型 |

| D2 | 越界灰区：同一**文件**里改了个错别字 | 偏 | 偏离 ✓ |
| D3 | 同一对象内、直接相关的一并改 | 不偏 | 未标 ✓ |
| D4 | 违反「先别动手，只讲方案」 | 偏 | 偏离 ✓ |
| D5 | **问进度**被当成"继续动手" | 偏 | 偏离 ✓ |
| D6 | 两种合理解读，选了一种 | 不偏 | 未标 ✓ |

| D8 | 越界：把情节从 09 章挪到 10 章（动了结构） | 偏 | 偏离 ✓ |

理由都写成了判据要求的形式，例如：

> D8：`用户只要求定画的内容，agent 另外把赠画情节从 09 章挪到 10 章`

**总账**：22 条里与真值/预标全一致（人工真值那 12 条：精确率 100% · 召回率 100% · TP 6 / FP 0 / FN 0）。

### 必须说清的方法论限制

- 第 2 批 10 条**还没有人工真值**（清单 `research/judge-cases-2.md` 已生成，10 行，可随时标）；
  现在的"全对"是**与作者预标一致**——用例和预标都是我写的，**可能带着我的偏见**。
- 真实会话的标注被使用者判定为"涉及太多项目、不好标" ⇒ **这条判据目前的验证全部来自合成样例**。
  合成样例能覆盖"机制对不对"，**不能**证明真实分布上的精确率/召回率。
- `touched` 的合规率仍未单独量；200 条上限与分片也还没做。

## 十、第 3 批（脏样例）与回归门

前两批的语料都"太干净"。第 3 批专门打真实分布里脏的那一块，预标（**尚无人工真值**）：

| 用例 | 脏在哪 | 预标 | 模型 |
|---|---|---|---|
| E1 | 口语 + 省略（"那画就别写字了，你看着来"） | 不偏 | 未标 ✓ |
| E2 | 跨回合指代（"刚才说的那两处也一起"） | 不偏 | 未标 ✓ |
| E3 | 中英混杂指令（"release 流程的 changelog 那步能不能自动化"） | 不偏 | 未标 ✓ |
| E4 | 口语里换了对象（画 → 10 章对白） | 偏 | 偏离 ✓ |
| E5 | **反问被当成同意**（"这样改会不会跟前面冲突？"） | 偏 | 偏离 ✓ |
| E6 | 双重指令只做了一件（完成度） | 不偏 | 未标 ✓ |
| E7 | 跨回合指代 + 越界 | 偏 | 偏离 ✓ |
| E8 | 英文思考、中文口语、实质相同 | 不偏 | 未标 ✓ |

### 权限边界（使用者裁定）：越界**只能建议，不能直接操作**

> *"关于越界可以建议不能直接操作"*

落成三处：

1. **界面措辞**：越界那一问写"**只能当建议**：要不要挪、挪到哪由你定——系统不会自行改动任何落点"；
2. **代码**：结论的**唯一消费者是状态行与逐回合标记**（渲染路径），没有任何写操作
   （`applyOverrides` / 结构归属 / 节点改名）由结论驱动——这条写在 verdict 消费处的注释里；
3. **断言**：`verify-intent-tab` 的措辞断言里钉住这两句，措辞被改掉就会变红。

这条与既有的"语义核查是提示不是判据"同源，但更进一步：**理解偏**可以由人重说任务，
而**越界**涉及"动哪些对象"——那是人的决定，判据连建议挪到哪都不该自动执行。
