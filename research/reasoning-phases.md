# 思考有没有位置结构？——对一条直觉的检验

> 被检验的主张（来自本项目用户阅读会话后的直觉）：
>
> > 思考应当**有意筛选区分**：靠前的那段（第一项或较前的思考）可能在**重申用户的
> > 目标意图**，并且**代表上一轮对话里 agent 提到的设计**；后续的思考更多是
> > "目标定下之后的执行思路"。
>
> 工具：`tools/measure-reasoning-phases.mjs`（可复跑，读 `~/.dsh/sessions/**/session.v3.jsonl.zstd`）

## 为什么先测再做

这个项目已经栽过两次同一类亏：**把机制推断当成结论**——压缩混淆那条被自己的检验
否掉；外部评审 §4 那条的前提根本不成立。所以这条直觉也按同一把尺子过：
**要么测出来，要么降级。**

它有后果：若成立，面板就不该把思考当正文看待，而该**按位置筛**——
靠前那段才是"这一段在做什么"的独立佐证，而且是**不来自用户措辞**的佐证。

## 怎么测

- 语料：**6 个会话 / 769 个可用回合**（可用＝回合内 ≥2 个带思考的步；只有 1 步的
  123 个回合无法比位置，排除并报数）。
- 位置取三档：**前＝第 1 步 / 中＝第 ⌊n/2⌋ 步 / 后＝最后一步**。
  第一版只比"前 vs 后"，而**回合的最后一步常常是写总结**——三档才能看出走势。
- 度量用插件自己的函数：`bigrams` / `overlap` 从 `lib/shared/intent.js` 引入，
  **不另写一份**（"两个实现在同一语料上漂移"是本项目吃过的亏）。
- **每个量都配错配对照**：字符二元组在无关文本之间本来就有约 0.23 的底噪，
  绝对值没有意义，只有相对差值有。

## 结果

| 量 | 前 | 中 | 后 | 错配对照 | 判定 |
|---|---|---|---|---|---|
| **H1 重申目标**<br>`overlap(思考, 本回合 prompt)` | **0.0559** | 0.0250 | 0.0180 | **0.0142** | ✅ **成立** |
| **H2 承接上轮**<br>`overlap(思考, 上回合思考)` | 0.4269 | 0.4041 | 0.3916 | **0.4025** | ❌ **不成立** |
| **H3 执行痕迹**<br>`overlap(思考, 本回合工具参数)` | 0.2736 | 0.2618 | 0.2511 | — | ❌ 方向相反 |
| **H4 接住上轮的具体产物** | 0.2876 | 0.2436 | 0.2562 | **0.0931** | ⚠️ 承接是真的，但**不集中在靠前** |

### H1：成立，而且很干净

- 三档**单调下降**（0.0559 → 0.0250 → 0.0180），**6/6 会话方向一致**，66% 的回合单调下降。
- 关键是错配对照 **0.0142**：**后段的 0.0180 基本就是底噪**——靠后的思考几乎不再谈目标；
  而**前段是错配的 3.9 倍**。
- 先堵一个最容易被提的质疑：会不会"前段"天然更长？**不是**——
  取样规模前 165.1 / 中 161.5 / 后 166.6 个二元组，基本相等；
  未截断（<400 字）的比例 10.3% / 14.6% / 19.5%，**后段反而更常是短文本**，
  而它的重合度仍然最低。这个差不是窗口大小造出来的。
- 人话样本（`session-f1cd07` 第 2 回合）：

  > **prompt**：裁决项先延后，前核对修改内容是否协作规范，以及你已经充分了解了小说的主要设计内容和故事剧情
  > **前思考**：*The user asks two things: 1. 核对我刚才的修改内容是否符合协作规范 2. 确认我是否已经充分了解… "裁决项先延后" — defer the pending decisions…*
  > **后思考**：*…Now write the answer. Note: check_prose still reports 12 items… Let me write the final response covering both questions…*

  前段是**逐条复述用户要求**，后段是**怎么把汇报写出来**。

### H2：不成立——被对照吃掉了

"与上一回合思考的重合"是 0.4269，看起来很高；但**与远处回合思考的重合是 0.4025**，
几乎一样。也就是说那个 0.43 是**话题底噪**（整段会话用词本来就高度重叠），
**不是承接**。逐会话方向也不稳：两个会话是前 < 后。

> 这条是本轮最有价值的否证：**若只看 0.43 这个数，会得出"承接被证实"的错结论。**

### H3：方向相反

"靠后是执行思路"应当让后段与**本回合工具参数**的重合上升——实测三档都在**降**。
原因大概是我的"后段"取到了**最后一步**，而它通常是**写总结**的那一步。

### H4：换一个更尖锐的度量，承接是真的，但不看位置

词面重合测不出承接，就换成**具体产物**：文件路径、`#N`、反引号里的标识符。
（产物稀疏，所以 H4 用**整段**思考，不用 400 字窗口——第一版用窗口，
只有 107/769 个回合算得出值，走势被"哪一段恰好提到路径"决定了。）

- 三档 0.2876 / 0.2436 / 0.2562，错配对照 **0.0931**（远处回合的产物）。
- ⇒ **承接确实存在（约 3 倍于远处基线），但它分布在整段思考里，不是靠前那一段的特性**：
  单调下降只有 118/306（39%），逐会话还有升的。

## 结论

**思考确实有位置结构，但只有一条轴，而且只在第一半成立：**

| 主张 | 判定 |
|---|---|
| 靠前的思考在重申用户的目标意图 | ✅ **成立**（前 0.0559 vs 后 0.0180，错配 0.0142） |
| 靠前的思考代表上一轮 agent 提到的设计 | ⚠️ **承接是真的，但不集中在靠前**（H2 被对照否掉，H4 三档都高） |
| 靠后的思考是执行思路 | ❌ **没测到**（三档都在降；末步多是写总结） |

## 对产品的含义（值得做的部分）

1. **靠前的思考是一份"不来自用户措辞"的目标证据。** 面板现在测"这一段在做什么"
   用的是 prompt + response。而前段思考是 **agent 自己对用户意图的复述**——
   来源不同，可以互相验证。
2. **它可以当分组的第二个独立信号。** 当前分组的唯一信号是词面重合度
   （TextTiling 家族）。若某回合的**前段思考与组目标不再重合**，而词面仍与组内相似
   （因为工具名、文件名还在），那就是**"表面连续、目标已变"**——
   现有度量看不见这种情形，两份不同来源的量一起指向才是更可信的分界。
3. **代价可控。** 只取每回合头 400 字：91 回合 ≈ 36 KB，比全文（同会话思考 336 KB 量级）
   小两个数量级；若只在 fold 里算成**一个标量**（前段思考与当前组目标的重合度）
   而不留正文，投影载荷几乎不增加。

# 第二段：这个信号**有用**吗——两次否证与一个可行用法

第一段只证明了**信号存在**。这一段问的是它会不改变产品。

工具：`tools/test-early-reasoning-signal.mjs`、`tools/test-goal-statement-signal.mjs`
（两者与上文的工具共用 `tools/session-log.mjs` 这一份载入实现）。

## 试法一：拿它当**第二个切分判据** → 否证

> 切分条件从 `连续性 < T` 改成 `连续性 < T 或 前段思考相关度 < T`。

**第一版这个实验我自己做错了两次，两次都写在脚本头里当教训：**

1. **拿不同阈值比。** 我比的是 `or@0.04` 与 `base@0.08`，于是"变好"完全可能是
   **把阈值调低了**（切得更少），新信号一点没参与。实测正是如此：`base` 自己
   在 0.04→0.12 上的 WindowDiff 是 0.5251 / 0.6133 / 0.6932 / 0.7188 / 0.6597
   ——**阈值的影响比信号大一个量级**。
2. **没有安慰剂。** 新信号只要让"切得更少"成立是不够的——随便换个信号也能做到。

改对之后（同一阈值比 + 安慰剂把每回合的前段思考换成别回合的）：

| 阈值 | base WD | or WD | **orShuf WD（安慰剂）** | base→or 边际 |
|---|---|---|---|---|
| 0.04 | 0.5251 | 0.5448 | 0.5368 | **+0.0197（更差）** |
| 0.06 | 0.6133 | 0.6015 | 0.6021 | −0.0118 |
| 0.08 | 0.6932 | 0.6872 | 0.6771 | −0.0060 |
| 0.10 | 0.7188 | 0.7130 | 0.7101 | −0.0058 |
| 0.12 | 0.6597 | 0.6486 | 0.6524 | −0.0111 |

⇒ **边际效果 ≤0.012、符号还不稳，而安慰剂在 5 个阈值里有 3 个比真信号更好。**
**这个用法不成立。**

（顺带一个陷阱：`and` 变体在表上最好看——WindowDiff 0.4250–0.5018——
但那是因为它**退化成 4.7–10.6 个组**：1000 多个回合切 5 组，判据已经没信息了。
"最好看"和"退化了"在 WindowDiff 上长得一模一样。）

**外部锚点也没能救它**：用真实的 `goal/change` 与标题重算当参考，
所有变体（含安慰剂）的分界落在锚点 ±2 内的比例都是 **3–5%**，
而 7 个会话总共有 14 个锚点、每会话约 20 个分界——**这个检验没有功效**，
既不能支持也不能否证，只能如实说"n 太小"。

## 试法二：换成**不同族的表示**（抽出"目标句"）→ 有用，但只在一个地方

词面重合与连续性判据**同族**（都是"这段文字有多少词在组里"），所以加不出独立信息。
换一个不同族的：从靠前的思考里抽出**一句被归一化的话**——"这一回合把用户要什么
说成了什么"（`The user asks two things: …` 这种）。

抽取器先自检：抽出的句子与**本回合 prompt** 的重合 **0.0857**，
与**别的回合 prompt** 只有 **0.0202**——**4.2 倍**，说明它确实抓到了用户的要求。
抽取率 **60%**（逐会话 33%–73%）。

然后看它是不是"组内稳定、分界改变"：

| | 值 | n |
|---|---|---|
| 同组相邻两句重合 | 0.3223 | 321 |
| **跨分界两句重合** | **0.2562** | 56 |
| 安慰剂（跨 7 回合） | 0.2825 | — |

方向对（分界处确实更低），**但没有过预先定的那条线**：同组/安慰剂只有 1.16 倍
（定的线是 1.2）。而且**这个比较本身有循环**——目标句是对 prompt 的复述
（自检那 3.9 倍就是证据），而分组本来就是在 prompt+response 的词面上切的。
**"复述变了"所以"分界对了"近乎同义反复。**

### ⚠️ 语言混淆：这一节的数字被用户当场指出了一个硬伤

> 用户："实际部分人工智能模型思考时可能采用中英文混合，单纯文本召回不靠谱"

**他是对的，而且比我想的更严重。** 工具：`tools/test-language-mixing.mjs`（1031 个回合）。

**① 思考的语言构成**：**英文 83% · 中英混合 15% · 中文 2%**。
会话是中文的，思考是英文的——这是默认状态，不是例外。

**② 抽取器有语言偏向（这条是真 bug，已修）**：

| 思考语言 | 修前命中率 | 修后 |
|---|---|---|
| 中文 | **15%**（3/20） | **100%**（20/20） |
| 英文 | 60%（512/854） | 63%（538/854） |
| 混合 | 39%（60/155） | 50%（77/155） |

漏掉的是这类句子（**目标明明写在里面**）：

> 「**用户同意**在画上不加任何文字……现在**我需要**把这段内容落实到第09章」
> 「**用户指出**第11章中存在一个矛盾……**我需要**检查第11章」

第一版的中文线索只有 `用户(要求|想要|希望|说|问)` 与 `目标是`——**"同意/指出/强调/
确认"和"我需要"全都不在词表里**。补上之后中文从 15% 到 100%。

**③ 93% 的"复述句 ↔ prompt"配对是跨语言的**：

| prompt→复述 | 条数 | 占比 | 平均重合 |
|---|---|---|---|
| **中文→英文** | 415 | **65%** | 0.0342 |
| 混合→英文 | 116 | 18% | 0.1509 |
| 中文→混合 | 58 | 9% | 0.3251 |
| 中文→中文 | 31 | 5% | 0.1435 |
| 其余 | 15 | 2% | — |

⇒ 字符二元组**跨语言结构性地对不上**（0.0342 对同语言的 0.1435–0.3251）。

**这决定了哪些数字能读、哪些不能：**

| 数字 | 能不能读 | 为什么 |
|---|---|---|
| 抽取器自检 **4.2 倍**（本回合 vs 别回合 prompt） | ✅ | 分子分母都是"英/混句子 vs 中文 prompt"，损耗一样 |
| H1 前/中/后 **0.0559 / 0.0250 / 0.0180** | ✅ | 同一个句式下比位置，损耗一样 |
| H2 / H3（思考 vs 思考） | ✅ | 英文对英文，本来就不跨语言 |
| H4（产物） | ✅ | 路径 / `#N` / 标识符**不分语言** |
| **简报回合"prompt 0.0016 对复述 0.0186（11 倍）"** | ❌ **撤回** | 中文 prompt 与中文**组**比、英文复述与中文**组**比，**两个测量口径** |

⚠️ 注意混淆的方向：跨语言会让复述**偏低**，而它仍然比 prompt 高——所以**方向**
不是假的，但**那个倍数**没有意义。**我不该用它当论据，已从代码注释与断言里撤掉。**

**跨语言唯一的共同通道是具体产物**（路径 / `#N` / 反引号标识符 / 数字）。
用它在简报回合上再量一次：prompt **n=0**（211 个简报回合里，带产物的 prompt
是 0 个），复述句 n=10、与组内产物的重合 0.60。**样本太薄，只能当旁证。**

⇒ 所以"简报回合显示复述句"这条产品判断，现在**不再引用那个 11 倍**，
改用一个语言中性的说法：**那种回合里用户的原话没有任何具体指称**
（短于 12 个二元组、产物记号 0 个），而 agent 的复述是完整的一句话。

### 唯一站得住的用法：**简报回合**

`BRIEF_PROMPT` 那条实测早就写了：**26% 的 prompt 是 `同意`/`继续吧`/`帮我重启`**
——承接与指令，**用户的话里根本没有目标**。只在这些回合上看：

| | 与当前组的重合 | 能不能读 |
|---|---|---|
| prompt（用户原话，中文） | 0.0016 | ❌ 与下一行**不同口径** |
| 目标句（agent 的复述，多为英文） | 0.0182 | ❌ 同上 |

n=211 个简报回合。**这个对比已撤回**（见上节的"语言混淆"）。
可用的替代说法是语言中性的那一条：**简报回合的 prompt 里产物记号是 0 个**
（211 个里 0 个），而抽出的复述句在 10 个回合里带产物、与组内产物重合 0.60。

⇒ **结论：不要拿它当切分判据；可以拿它当"简报回合的显示文本"。**
面板现在对这类回合显示的是 `同意` 或`（本轮无提问）`——正是它没信息的地方。

### 落进产品时被断言抓到的一个真 bug

抽取器搬进 `src/shared/intent.ts` 之后，给它加的第一批断言里有一条
`抽得出中文目标句` **当场失败**：断句用的是
`split(/(?<=[.!?。！？])\s+|\n+/)`——要求终止符**后面有空白**。
英文成立，**中文不成立**（`。`后面通常没有空格），于是整段中文被当成一句话，
"目标句"变成 200 字的整段。改成中英分开处理（`.`/`!`/`?` 后仍要求空白，
否则 `docs/44`、`0.08` 会被劈开；`。！？` 后不要求）。

修完上面那些数字有轻微变化（本节引的都是修后的值）。

## 还没验的（不要当成已成立）

- **接进去是否真的改善分组/漂移检测**：本轮只证明了"这个信号存在且位置稳定"，
  没有证明它比现有度量更准。要证得做一次**来源不同**的对照实验——
  而这正是本项目 `scripts/segment-quality.mjs` 那套 WindowDiff/Pk 的用武之地。
- **前段思考 vs response，谁更能代表该段意图**：未测。
- 语料是 6–7 个会话、且都是同一个用户的工作方式；换人换域是否仍成立，未知。
- **"简报回合显示目标句"只是测出它带了信息，没测过显示出来好不好用**——
  那是产品判断，得看界面。
- 只用了 H1 这个"字面重合"口径；**复述不一定要用原词**（换同义词就测不到），
  所以 0.0559 应读作**下界**，不是强度。
