# 任务结构规格（由使用者的六条裁定推出）

出处：`research/synthetic-session-a.md` 那六问。使用者**看着虚构语料**作答，
所以这是**判据**，不是回忆。

## 六条裁定（原话）

| # | 问 | 使用者 |
|---|---|---|
| 1 | 四个根对不对 | **对的**（部署 / 缓存 / 登录 / 收尾） |
| 2 | 子节点该不该合并 | **不合并**——"考虑到任务可能会继续分支" |
| 3 | `#22–26` 接回「部署」 | **可以接回**——"任务有关联" |
| 4 | `#25–26` 归部署还是缓存 | "如果同个对话存了几个任务的内容，**几个任务下都放**" |
| 5 | `#21` 天气那句 | **零散节点** |
| 6 | 父区间管自己还是含子 | **拆分节点的** |

## 推出的结构：**不是树，是允许重叠归属的 DAG**

1. **一个回合可以同时属于多个节点**（第 4 条）。
   ⇒ **既有的"把回合序列切成若干段"从根上错了**——目标不是**划分**（partition），
   是**多对多的归属**。这解释了前九段为什么所有精确率都难看：
   拿一个划分去交一份重叠归属的卷。
2. **"零散节点"是一种节点**（第 5 条）：插话/闲话不该被丢掉，也不该塞进某个任务，
   而是**自成一个小节点**。⇒ 节点要有 `kind`：任务 / 零散。
3. **父节点是纯容器**（第 6 条）：父不能"直接拥有"散落的回合——
   那些回合该**各自成节点**。⇒ 不变量：**每个回合至少属于一个非容器节点**；
   容器节点只负责把子节点归堆。
4. **可以接回**（第 3 条）：同一节点可以有**多个不连续区间**。
5. **不合并**（第 2 条）：宁可留细，因为细节点将来还能继续分支。
   ⇒ 合并是**展示时**的事（折叠），不是**建树时**的事。

## 建议的 schema

```json
{
  "nodes": [
    {"id": 1, "parents": [0], "title": "部署脚本排障", "kind": "task"},
    {"id": 2, "parents": [1], "title": "sudo 两次问题", "kind": "task"},
    {"id": 9, "parents": [1, 4], "title": "目录权限", "kind": "task"},
    {"id": 10, "parents": [], "title": "（闲话）天气", "kind": "aside"}
  ],
  "membership": [
    {"turn": 25, "nodes": [2, 9]},
    {"turn": 21, "nodes": [10]}
  ]
}
```

- `parents` 是**数组**（重叠归属允许一个节点挂到多处）；
- `membership` 是**逐回合的归属列表**，一个回合可以对多个节点；
- `kind` 至少两类：`task` / `aside`；
- **不变量**：每个回合至少出现在一个 `kind != container` 的节点里；
  区间由 `membership` 现算，**不写死**（否则又回到"连续区间"的老毛病）。

## 现在的模型输出违反了哪几条

| 裁定 | 模型（合成语料 A） | 违反 |
|---|---|---|
| 4 多归属 | 把 `#25–26` 只放在「部署」下 | ✗ |
| 5 零散节点 | `#21` **整条消失**（不建节点、也不在任何区间） | ✗ |
| 6 父为容器 | 父区间 `#1–2 , #22–26` 与子区间**不构成包含关系** | ✗ 但方向对了一半 |
| 2 不合并 | 没合并 ✓ | ✓ |
| 3 可接回 | `#22–26` 正确接回 ✓ | ✓ |
| 1 根 | 四个根，使用者确认 ✓ | ✓ |

⇒ **树那一层是对的，划分假设是错的。** 六个里对三个，错的三个全部源于
"一个回合只能属于一个节点"这个隐含前提。

## 还没验的

- 模型**能不能**产出多归属 + 零散节点（schema 与提示词都要改，未跑）；
- `kind` 的取值集合是不是只有两类（使用者只给了"零散"一词）；
- 一个回合属于多个节点时，**面板该怎么显示**（现在没有这个表达）；
- 全部来自**一场合成语料**的判断。真语料上是否同样适用，未知。
