# 议题边界：用合成语例标定判据

## 为什么要这个

`research/semantic-space.md` 第八段卡在一件事上：**"精确率"没有参考可判**。

- 我能拿到的唯一外部锚，是使用者**显式宣布**的切换（12 个）——那只是真切换的**子集**；
- 拿子集当参考算精确率，**会惩罚任何比参考更细的检测器**（模型切 38 段、参考 5 个边界，
  "多切 33"里有多少是真的，参考没资格判）。

⇒ 缺的不是更多算法，是**一份"什么算议题切换"的判据**。这份判据只存在于使用者脑子里，
所以只能用**选择**把它取出来。

## 设计：合成语例 + 固定候选边界

语例是**造的**（不是使用者的真实会话），这样能控制每一例想探的**那一个维度**。
每一例给 3–5 个回合，**候选边界固定放在中间**，选项只有三个：

- **A 是**：这里确实换议题了
- **B 不是**：还在同一个议题里
- **C 不确定 / 看情况**

八例分别探八个维度（下表是**我预设的答案**，先不告诉使用者，用来标定他的判据）：

| # | 探的维度 | 我预设 |
|---|---|---|
| 1 | 明确宣布的切换（"接下来看另一个问题"） | 是 |
| 2 | 同一议题下的**子问题**（"顺便说一句这个命名"） | 不是 |
| 3 | **未宣布**的真切换（问完部署，直接问薪资期望） | 是 |
| 4 | 中间插一句无关的，随后**回到原议题** | ?（这是最想学的） |
| 5 | **词面平滑**的切换（同一批术语，议题从"设计"变"排期"） | 是 |
| 6 | **词面突变**但仍是同一件事（从写代码转到写测试，同属"实现这个功能"） | 不是 |
| 7 | 收尾/汇总（"那就这样，我汇总一下"） | 不是 |
| 8 | 因**纠正**而导致的方向修正（agent 做错了，改回来继续同一件事） | 不是 |

预设里两处打问号/待校准的地方，正是**标定的价值所在**：
如果使用者的判据是"换议题 = 换了'要产出什么'"，那么 4 可能判"不是"、5 判"是"；
如果他的判据是"换议题 = 换了讨论对象"，结论可能相反。

## 标定完之后怎么用

1. 把使用者的答案当作**判据**（不是当作标签去训模型）；
2. 用它去判**模型提议的那些边界**——只需人看十来个；
3. 再算精确率/召回，那两个数字才有意义。

⚠️ **合成语例能标定判据，不能测检测器**：检测器要在真实语料上评。
这一步只解决"什么算切换"。

# 标定结果（使用者已作答）

| # | 使用者的答案 | 他给的理由 |
|---|---|---|
| 1 | **A** | 从 logrotate 换到环境变量，可能是**同个部署任务的子任务切换** |
| 2 | **A** | 从数据输出到函数，可能是**同个 sql 任务的子任务切换** |
| 3 | **A** | 从软件部署到招聘，**领域大转换** |
| 4 | **B** | 中间用户切入了天气话题，但**助手自己回到了任务** |
| 5 | **B** | **仍然是缓存讨论** |
| 6 | **B** | **仍然是登录模块的调整** |
| 7 | **B** | **同个任务的汇总** |
| 8 | **B** | **同个任务** |
| 9 | 看任务难度 | 修某个模块 → 3–5 个；**调研任务 → 20 个以上** |

## 取出的判据

**判据是"正在弄的那个东西变了没有"，不是"话题词变了没有"。**

- **算切换（A）**：换了**对象/子任务**——logrotate → 环境变量；数据输出 → 函数；
  部署 → 招聘。**连"同一个大任务下的子任务"也算。**
- **不算切换（B）**：
  - **同一个对象换个侧面**——缓存的设计 ↔ 缓存的排期（5）；
  - **同一个模块换个动作**——登录的重试逻辑 ↔ 登录的测试（6）；
  - **汇总**——同任务的收尾（7）；
  - **纠正**——同任务的方向修正（8）；
  - **插话后回到原任务**——天气那句之后助手把话拉回来（4）。

一句话：**议题 = 处理中的那个具体对象；边界 = 对象变了。**
不是措辞、不是"侧面"、不是"宣布没宣布"。

## 这对前面的测量意味着什么（重要）

**我那个锚是错的参考。**

锚 = 使用者**显式宣布**的切换（12 个）。而那些宣布的几乎都是**大转换**
（"接下来看另一个问题"）。可他的判据里**子任务切换也算**——
子任务切换远比宣布的频繁，而且**大多数不会被宣布**。

⇒ "模型切 38 段 / 参考只有 5 个边界 → 多切 33"里，**那 33 个很可能大部分是合法的
子任务切换**。用宣布的切换当参考，等于**拿"大事件"的标签去评"细粒度"的检测器**——
这正是第八段那个"子集参考"错误的根源，现在有了机制解释。

也解释了为什么**强制变粗会让召回从 64% 掉到 9%**：
宣布的那些切换点**不在**粗粒度边界上，因为粗粒度把子任务都合并了。

## 因此下一步

需要在**真实语料**上取一份"对象变了"的标签——而这份标签**只能由使用者给**。
做成**十来个候选边界 + 上下文**的选择题（A 是 / B 不是 / C 不确定），
候选**优先取模型切出来的那些**（因为词面基线切得更碎且更乱）。

拿到这份标签之后，精确率才第一次可测——而且**判据是使用者的，不是我的预设**。

# 结构修正：任务更像**树**，不是一条被切开的线段

> 使用者："我觉得会话里面的任务可能更接近于**树状结构**"

## 证据其实早就在手里

第八段让模型给议题标题，`f1fa55` 那一场它给出的是（原文照抄）：

    个人资料基础信息收集 / FDE方向包装与个人资料纲要 / 个人资料内容补充与打磨 /
    项目细节调整与求职意向 / 个人资料排版与HTML/PDF输出 / 在线个人资料解析与平台调研 /
    广州岗位薪资期望评估 / AI经纪人网页项目搭建部署

**前六个全是"个人资料"底下的兄弟子任务，最后一个是另一根枝。** 模型本来就在输出
**父子/兄弟结构**，只是我逼它压成了一条**平铺的段序列**——把树拍平了。

再对照标定出来的判据（"正在弄的那个东西变了没有"）：

| 标定例 | 树上的位置 |
|---|---|
| 1 logrotate → 环境变量 | **兄弟**（同一个"部署"父节点下） |
| 2 数据输出 → 函数 | **兄弟**（同一个"sql 任务"下） |
| 3 部署 → 招聘 | **另一根枝** |
| 4 天气插话后回到任务 | **临时离开又回来**（平铺模型表达不了"回来"） |
| 5 缓存设计 → 缓存排期 | **同一个节点**（换的是侧面） |
| 6 登录重试 → 登录测试 | **同一个节点**（换的是动作） |
| 7 汇总 / 8 纠正 | **同一个节点** |

⇒ **平铺分段模型与这份判据根本不匹配**：它分不出"兄弟"和"另一根枝"，
也表达不了"离开又回来"，而这两件事恰恰是判据里最要紧的区分。

## 因此要换的是**模型本身**，不只是参数

- **原来**：把回合序列切成若干段（我一直在调的那个东西）；
- **应该是**：把每个回合**归到任务树上的一个节点**，节点有父子、有兄弟；
  于是"切换"有三种——**下钻**（进子任务）、**上浮**（回父任务）、
  **平跳**（兄弟或换枝）——而"留在同一节点换侧面"不是切换。
- 这同时解释了第 9 题：**粒度取决于深度**——修模块的任务树浅（3–5 个节点），
  调研任务的树深（20+）。平铺分段只能用一个段数去近似它，必然两边都不对。

## 对前面的测量意味着什么

前八段所有"精确率/召回"都在评一个**被拍平的树**。所以那些数字低，未必是
检测器差，而是**目标函数选错了**——它逼一个树状的东西按线性去交卷。

## 下一步（具体）

1. 让模型对**一场真实会话**输出**任务树**（嵌套：节点名 + 起止回合 + 子节点），
   而不是段序列；
2. 把树**给使用者看**，让他改（哪几个该合并、哪个该上浮、哪个是另一根枝）——
   这一次的产出不是"标签"，而是**结构本身**；
3. 有了树再谈度量：那时"切换"有了明确的三种类型，精度可以**分类别**算，
   而不是拿一个笼统的精确率去盖。

⚠️ 提醒自己：**这一步仍不是"验收"**。树是候选，使用者改过的树才是真值；
而在拿到真值之前，别再用"精确率"讲故事。
