# 真 DAG 分支：第一次实测到（合成语料 `synthetic-shared-task`）

## 结论先说

**流水线本来就能长出多父节点，不需要改提示词或数据结构。**
五场真实会话里一次没出现，是因为**那些会话真的没有共享子任务**——不是能力缺口。

## 怎么造的语料

`research/synthetic-shared-task.txt`（32 回合）：一次会话里**两件事并行**
（给客户做的库存看板 + 自己的作品集网站），而它们**都需要同一个东西**——
一套能在两边跑的部署脚本。第 #3–#4、#14–#16、#21–#23、#27–#28 都在弄这一个对象。

## 跑出来的结构

```
库存看板 ← #1…              作品集网站 ← #1…
├─ n3 部署脚本通用化 ← #3–4、#14–16、#21–23、#27–28   [↩ 同 n3]
│  ├─ n4 路径改环境变量 ← #5
│  ├─ n5 日志统一目录 ← #6
│  └─ n11 客户服务器试跑 ← #12–13
```

`n3` 的 `parents` 是 **`['库存看板', '作品集网站']`** —— 这正是使用者最早那句
"**如果同个对话存了几个任务的内容，我觉得应该几个任务下都放**"的形状。

渲染侧也验证过：`renderTree` 在**两个父下各画一次**，重复那次标 `↩ 同 n3`
（`research/dag-label-sheet-synthetic-shared-task-2026-10-09.md` 第 21、31 行）。

## 数据与开销

- 6 次调用 · 输入 2573 / 输出 631 tokens（`--cut 12 --chunk 10`）
- 结构轴：`id ✓ 父 ✓`；覆盖 32/32；异支多落点 3
- 根：2 条非插话线（库存看板 / 作品集网站）+ 1 条插话根（明天客户开会）

## 还没定的一件事

多父节点在**面板上怎么显示**：现在定义是"两个父下各出现一次"（信息不丢，但同一件事
在两处出现）。另一种做法是只在一处显示、另一处给个链接。这属于展示层，
等接线到插件时再定；数据层不需要改。
