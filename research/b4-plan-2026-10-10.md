## 四个切片（每片 = 一次提交 + build 全绿 + 真跑一次）

### B4-1 选中回合 → 改落点（最小可用）

- **入口**：会话行（树上）与详情层的每一行给一个"改落点"按钮；
- **编辑器**：就地展开一个面板，列出**全部节点标题**（当前落点已勾选），勾选即改；
  另有"新增节点"（给没处放的回合）；保存 / 取消；
- **写路径**：`validateOverrides` →（内存即时生效）`applyOverrides` → `saveOverrides`；
- **渲染**：在 `useMemo` 里把覆盖叠在 `/api/intent.structure` 的结果上，
  所以改完**立刻重绘**（回合从旧节点移到新节点）；改过的行标 `改过`，
  带**单条还原**与**全部还原**；
- **未归属行**也要能挂上去（现在结构里 `unattached` 是只读展示）；
- **断言**（离线，`verify-intent-tab` + `verify-task-graph`）：编辑器渲染、
  勾选产生正确的 op、渲染反映覆盖（旧节点少一条、新节点多一条）、`改过` 标记与还原。

### B4-2 节点改名 / 合并 / 删除

- 节点行给菜单：**改名**（就地输入）、**合并到…**（选目标节点）、**删除**（落点如何处置要明说）；
- 复用同一套 op 与写路径；
- **断言**：改名改的是树上的标签；合并把落点搬过去并删掉源节点；删除后其落点变成未归属。

### B4-3 收编"基线编辑"→ 会话/根节点改名；删掉旧 baseline 机器

- 现状（代码证据）：基线**只剩三处显示**（头部标题 `model.rootLabel`、
  `基线：我的编辑/会话目标/会话标题` 标签、一句备注），**不参与任何计算**——
  它的主消费者（贴合度）随组口径下线了；还自带 `graph-view:intent-baseline:*` 的迁移。
- 处理：头部那个编辑入口改成**会话/根节点改名**（走 `rename` 覆盖），
  删掉 `readBaseline`/`writeBaseline` 与迁移代码，以及围绕它们的断言（**改指向，不是放宽**）。

### B4-4 持久化与真机验证

- 3098 实测：改一个落点 → **刷新页面** → 仍在；再看一次结构重算（增量）后是否仍在；
- 说明清限制：`scripts/e2e-panel.mjs` 只验"插件加载 + 零 console 错误"，
  **不驱动界面**（项目文档里记了驱动面板的三道坎）。所以这一条以**人工核对**为主，
  离线断言为辅——不假装它是自动的。

## 动手前要你裁的三件事

1. **覆盖以哪边为准**：现在有两条存储——浏览器 `localStorage`（真实用户就在浏览器里改）
   与宿主 `/api/intent.overrides` 的**内存 map**。我建议**以浏览器侧为准**，
   宿主那条路由降级为"研究/转发用"（或直接删掉，它的断言随之改指向）。
2. **改完之后，语义判定按哪份结构判**：现在语义材料取的是**宿主返回的原始结构**
   （`structure.structure`），不是叠了覆盖的那份。你手改完落点，标记却还按旧结构算——
   我建议**按叠了覆盖的结构**（与用户看到的一致）；代价是覆盖一变就要重判那些回合
   （逐回合缓存会兜住大部分）。
3. **越界的处置**：按你之前的裁定"**只能建议不能直接操作**"，
   我不做自动挪动；但可以在行上给一个**显式的人工入口**（"按建议挪回界内"= 一次点击的
   人工操作，仍由你按下）。要不要给这个入口？

## 不做的事（写清楚免得误会）

- 不做"自动修复"：判据只出建议（越界尤其如此），改动一律由人按下；
- 不把人工覆盖塞进结构流水线的提示词（否则"人改的"会污染"模型建的"，两者再也分不开）；
- 不动 GitHub/上游：B4 只在本插件内。

## 使用者裁定的三条（2026-10-10）

1. **持久化放在插件自己的部件内，怎么做由实现决定** ⇒ 定为：**浏览器侧 localStorage 是唯一权威**
   （键命名空间 `dsh-intent-view:*`，属于插件自己的部件），宿主那条 `/api/intent.overrides`
   路由与它的内存 store **删掉**（它的 15 条断言改指向共享校验——校验本来就只有一份）。
   理由：人就在浏览器里改，双份存储只会制造"哪份是真的"。
2. **"可以只判定涉及修改部分吗？"** ⇒ **可以，而且已经成立**——但这条断言**当场抓出一个真 bug**：
   逐回合键原先掺着 `task`（材料里的**位置编号**），而 `tasks` 只带被引用到的节点并**重新编号**，
   于是"把一个回合从 A 挪到 B"会让后面所有回合的编号整体位移 ⇒ **一次人工修改把整场判定的键全部作废**。
   修法：键改用**稳定身份 `node|nodeTitle`**（`SemanticTurn` 新增这两个字段，旧载荷缺字段时退回原样）。
   现在三条断言都在：被挪的那条键变、其余一个不变、被挪的那条确实换了节点。
   （附带一条方法论：那条断言第一次还写错了字段——比的是位置编号 `task`，而挪走后编号可能"看起来没变"。
   两处错误都是断言抓的。）
3. **回合标记要可人工修正**（人工修正模型的自动判定结果）⇒ 新增一个切片（见下 B4-3），
   与结构覆盖并列、同样落在插件自己的 localStorage 里。

## 空母枝：可以直接删（规则已实现，接线在 B4-1）

使用者："如果某个母枝变空了，那么应该可以直接删掉吧"。**规则必须先分清两类空**：

| 情形 | 例子 | 处理 |
|---|---|---|
| **空叶子**（无回合、无子节点） | `t45 清理项目名称与文档 ← （没有回合）` | **删**（纯噪声） |
| **空容器**（无回合、但有子节点） | `project 个人资料整理… ← （没有回合）` | **保留**（流水线设计：父节点是纯容器） |

按"没有回合就删"一刀切会把项目根与中间容器全删掉——那是破坏。

`shared/taskGraph.ts` 新增 `pruneEmptyLeaves(graph)`（纯函数、幂等、不动 membership），
四条断言：剪掉空叶子 / 空容器保留 / 有回合的节点保留 / 幂等。
**接线放在 B4-1**：生效结构 = `pruneEmptyLeaves(applyOverrides(原始结构, 覆盖))`，
只在那一处接（渲染与判定材料共用同一个"生效结构"）。

## 使用者三条新裁定（2026-10-10，第二轮）

1. **独立节点计数** ⇒ 已实现：`rootSummary` 的顶层判据从"`parents.includes('root')`"改成
   **"root 的孩子 ∪ 独立节点（`parents: []`）"**，并**排除 `root` 自身**（它的 parents 也是空数组，
   第一版把它自己数成了一条线——断言当场抓到：返回 `root,项目一,独立的一件事`）。
   断言：`verify-task-tree` 新增"独立节点计入线"。

2. **编辑空间"只能新增枝，不能新增节点"——节点对应真实回合** ⇒ 编辑控件的能力集定为：

   | 允许 | 说明 |
   |---|---|
   | 改落点 | 把**已有的回合**挂到别的节点上（回合是真实发生过的） |
   | **新增枝** | 建一个**分组/容器**节点（新的父），把已有节点挂到它下面 |
   | **挂枝（reparent）** | 一个节点可以同时挂在几个枝上（多父）——**现在没有这个操作，要新加** |
   | 改名 / 合并 / 删除 | 已有的 op |

   **不允许**"凭空建一个装回合的新任务节点"：那等于宣称发生了没发生的工作。
   要放某个回合，只能挂到已有节点，或先建枝再把节点挂上去。

3. **一个节点可以被挂到几个枝上**（多父）⇒ 这是真实形状，编辑时不能当成"移动"：

   - 树已经能画（多父节点在每个父下各画一次 + `↩ 同 nX`）；
   - 但**覆盖操作里没有 reparent**：现有 op 只有 `setPlacement` / `rename` / `merge` / `create` / `delete`
     （`shared/taskOverrides.ts` 的 `OVERRIDE_OPS`）⇒ **B4-2 的第一件事是加 `reparent`**
     （`{op:'reparent', id, parents:[…]}`：整份替换该节点的父集合），并配断言：
     加枝不动别的枝、去掉所有父 = 变成独立节点、成环要被拒。
