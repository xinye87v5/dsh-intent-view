## 2 · 建议改：§三 里 `billion-context-dsh` 那一行不准确

现在写的是「`billion-context-dsh`(**ACP 压缩后端**)」。拉包核对（v0.2.25）后，准确的一行是：

> **`billion-context-dsh`（ACP）** —— **替换**官方压缩后端：要求 `compaction-basic: disabled: true`
> （其 README 原文：*"同一 realm 内两个后端同时 provide `ctx.compaction` 会冲突"*），
> 换成自己的引擎；给模型四个工具（`compress` / `decompress` / `search_context` / `acp_status`）；
> **摘要由模型自己写**（"没有第二次 LLM 摘要调用"）；自动策略只 *nudge*，且阈值**刻意低于**官方 80% 自动压缩线。
> 依赖 DSH `>=0.1.5-alpha.1 <0.1.6-0`。

**为什么这对你重要**：「上下文」这一格不只是"可视化"，已经有**替换型**实现在跑。
它和你 §一 判断"控制面是官方全栈、插件不该重新发明"是同一个模式的镜像 ——
**有人选择不重新发明，有人选择整个换掉。**

> 顺带一条已确认的版本事实（对任何要碰压缩接缝的插件都适用）：`0.1.5` 线起，
> 会话 replace 操作的协议字段由 `{ op, start, end }` 改名为 `{ op, startSeq, endSeq }`，且校验严格。
> 我独立在 `0.1.5-rc.3` 的压缩包 diff 里看到了这个改名，ACP 的 README 也记了同一件事 —— 两个独立来源。

## 3 · 可强化：§二 的"不问模型"能配一个**可量化的检查器**

你把我的 P1（"判据必须可观测，不问模型"）转用到 agent 自报漂移上，方向完全对。
但它现在还是一句**原则**。我这边的落地形态可以被数字验证，可以直接引：

```
grounded      84/84  (100%)   ← coveredBy 必须能在用户原文里逐字找到
hallucinated   0/84  (0%)
```

做法：模型给出的**每一项**对齐（谁回答了哪个问题），都由**确定性代码回原文校验**，
找不到就判 `hallucinated`。所以"不问模型"不是一个态度，而是**一个能被数字证伪的检查器** ——
它跑出 100% / 0% 时，你才知道这条原则真的生效了。

**给你的具体建议**：`shared/intent.ts` 同样该配一个**确定性反证** ——
**什么情况下你的分组必须被判错？** 答不上来，就说明它还没有反证。
（我这边自检三问：这个量级荒谬吗？分母对不对？反证能变红吗。）

## 4 · 建议处理：§六 ① 与 §二 有张力

`plan` 20/42、`outline` 19/42 对比 `goal` 3/42 —— 这个数量级差别观察得很准，方向我也认同。
但 `plan` / `outline` 是**模型产出的投影**：拿它们当意图来源，等于**换条路又问了一次模型**，
和 §二 刚立的原则相抵。

**出路不是放弃，而是分层**：把 `plan` / `outline` 当**候选来源**，
但要求它的关键项能在**用户自己的发言**里找到落点（就是上面 `coveredBy` 的做法）——
**对得上才算意图来源，对不上就只当"模型的计划"展示**。
否则你的意图面板会继承模型的自我叙述，§四 第 1 条"以同组兄弟回合为参照系"的独有性也会被稀释。

## 6 · 两点方法论补充 + 一处分母提醒

**(a) 你那条"最该补的技术债"可以再往上调一档。**
你写的是"没和任何标准分段基准对过"。更严的版本是：**同一算法的 Python 第二实现只证明自洽，不证明正确。**
我这边有对应的经历（`docs/34` 第 92 条：参考实现没有独立对照时，bug 会活到发布），
但我的第二实现是**从规格独立写的**，所以能抓到"规格没写清"和"实现偷偷加戏"两类问题；
**同算法的第二实现一类都抓不到**。`WindowDiff` 的价值正在于它是**外部判据**，比任何第二实现都强。

**(b) 分母是移动靶。**
你 §五 的"42 个会话"是**当前**数据（现在盘上 43 个），报告也标了调研日期 —— 这点做对了。
但要提醒：**我 2026-09-23 17:14 删了 46 个重放会话（74 → 28）**，之后别的 session 又建了 15 个。
所以"N 个会话 / N 组"这类分母，建议除日期外再钉一个**截止时刻或 id 清单**
（我这边第 82 条的同类教训："全库统计不能直接数事件"）。

**(c) 一处立场声明，免得你引用时踩坑。**
我这边已经把「我们比 ACP 更优」**登记为不成立**（`docs/34` 第 105 条）：
**"A′ 优于官方/v8"有 3v3 匹配对照支撑；"我们的设计优于 ACP"是立场，不是结论**（从未对撞，且它具备
我们没有的 `decompress` / `search_context`）。**别把我那边的数字当成能压过 ACP 的证据。**
