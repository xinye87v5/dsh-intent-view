# 判定改成增量：只重判"变了的那些回合"（实测：36 条 → 1 条）

> 使用者："插件完成之后，新的会话都将是增量的，存量只要跑一次即可，后续成本应该不大吧"。
> 方向对，但**当时的实现不是增量**：两条路都按"整份材料的指纹"缓存，会话是活的，
> 新来一个回合整份指纹就变 ⇒ 每次都把选中的 40 条重判一遍。
> 这一步先解决语义判定那一侧；结构那一侧（增量归属）是下一件事。

## 做法：两级缓存

```
① 整份材料指纹（semanticKey）  →  什么都没变时一个 token 都不花（原有）
② 逐回合键（semanticTurnKey）  →  变了几条就只判几条（本次新增）
```

逐回合键 = `semanticFingerprint([该回合所在节点的材料行], ["回合号|指令|理解"])`。

**键里放什么、不放什么**（这是一处如实标注的近似，写在 `semanticTurnKey` 的注释里）：

| | 内容 | 理由 |
|---|---|---|
| 放 | 回合号、用户指令、agent 理解、**它自己那个节点的材料行**（标题 + 代表回合） | 节点改名/换样本会改变模型读到的上下文 ⇒ 这一条该重做 |
| 不放 | **同批其他节点** | 提示词里确实带着它们（`planBatches` 只裁到本批引用到的节点），编进键就等于"任何结构变化全批失效"，增量也就没了。**代价**：别的节点改名后，这条的旧结论会继续沿用 |

配套：`splitByTurnCache`（切"复用/新判"）、`rememberTurn`（写入 + 上限 5000 条按插入顺序淘汰）、
`sortByTurn`（合并后按回合号升序，界面按序渲染）。三样都导出，`verify-shared.cjs` 直接断言。

## 实测（3098 真模型，`f1cd07a6`，36 条待判）

宿主日志逐字：

```
收到判定请求 指纹=deadbeef-41 节点=40 条=36 带指令=36
增量判定：新判 36 条 · 复用 0 条          ← 冷跑（12 次调用 / 约 31 秒）
收到判定请求 指纹=deadbeef-43 节点=40 条=36 带指令=36
增量判定：新判 1 条 · 复用 35 条          ← 只改了 #90 一条理解（3 次调用 / 约 8 秒）
收到判定请求 指纹=deadbeef-42 节点=40 条=36 带指令=36
增量判定：新判 36 条 · 复用 0 条          ← 对调臂：36 条指令全不同，确实该全判
```

那条被改的 `#90` 也确实重判了（对调臂里它出现在被标列表里：*"用户要讨论角色甲-1赠小满画像的
内容，agent却在核查09章时间线，偏离了任务"*）。

**成本形状因此变了**：稳态下

- 新回合**没被选中**（不是简报/节点起点/压缩过）⇒ 材料没变 ⇒ 客户端**连请求都不发**，0 次调用；
- 新回合被选中 ⇒ **3 次调用（约 8 秒）**；
- 什么都没变 ⇒ 第一层指纹缓存直接返回，0 次调用。

对比这次改动之前：任何一条变化 = 重判 40 条 = 12 次调用（约 31 秒）。

## 面板上的账要露出来

`judged` / `reused` 随结果回到浏览器，状态行会写：

- `语义核查：… （36 条 · deepseek-official/deepseek-flash · 全部复用上次结论）`
- 或者 `… · 新判 1 条`

**为什么要把这个显示出来**：增量若哪天悄悄退化成全量重判，界面上要看得出来——
否则"成本为什么又上去了"只能靠翻宿主日志。

## 顺带记一条观测：同一材料重跑，真实臂 28% → 22%

| 运行 | real 被标 | ask-shuffled 被标 |
|---|---|---|
| 第一次（seq 21/31，只做三类口径那次） | 10/36（28%） | 24/36（67%） |
| 第二次（seq 41，本次） | 8/36（**22%**） | 24/36（67%） |

材料逐字相同、`temperature: 0`、3 票，结果仍差 2 条。与此前量到的"单票 18% 会翻面"
一致——**这类判据的数字要按区间读，不能按点读**（一次 36 条里 ±2 条是常态）。

## 这一步**没有**解决的（下一步）

**结构流水线仍是全量**：`/api/intent.structure` 按 `会话::contentHash::firstWindow::chunk`
缓存，`contentHash` 覆盖整场内容 ⇒ 新回合进来整场重算（`f1cd07a6` 实测 33 次调用 / 41.7 秒）。
要增量得把"新回合归属到已有结构"接进插件（算法形状在
`tools/probes/task-dag-incremental.mjs`：`newNodes` / `memberships` 出现即覆盖 / `reparent`，
其中一条标准正是"已有结构不许重排"）。它同时解决三件事：成本、节点 id 漂移、
以及**人工调整的落点不会被下一次重算冲掉**。

另外仍未验：真实臂那些被标条目**没有人核过**（模型给的理由读着合理，但那是模型的判断）。
