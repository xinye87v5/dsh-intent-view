# 任务结构流水线（**冻结版**）

> ⚠️ 本文件由 `tools/probes/render-pipeline-doc.mjs` 生成，提示词从
> `tools/probes/pipeline.mjs` 注入。**要改措辞就改那个模块**（或在
> `render-pipeline-doc.mjs` 里改叙述），然后重跑生成器；
> `scripts/verify-task-dag-pipeline.cjs` 会离线校验两者一致。

**它做什么**：把一段人与 AI 的会话整理成**任务结构**——允许重叠的图
（一个回合可以落在多个节点下），节点的父子是"这件事包含那件事"，
不是"回合的时间划分"。

**它由谁定形**：使用者对 `research/synthetic-session-a.txt` 上模型输出的
**八条人工标记**（`research/dag-labels-2026-10-09.md`），以及之后的三轮实测
（`research/structured-output-attempt.md`）。

## 一、三段（每一段都对应一条实测结论，**不要合并**）

| 段 | 输入 | 输出 | 为什么必须单独一段 |
|---|---|---|---|
| 建结构 | 前 N 个回合 | `{"nodes":…,"membership":…}` | 一次建基础结构 |
| 判归属 | 节点清单 + **新**回合 | `{"placements":…,"newNodes":…}` | **不带 ops 词汇表**：ops 例子里的 `assign` 只挂一个节点，等于示范"单一归属"（整批 ops 版多归属掉到 0/4） |
| 判整理 | **只有节点清单** | `{"ops":[…]}` | 合并只能在这一段发生——逐回合那一问只能*新增*，实测把"sudo 两步"记成 **3 个节点** |

二选一问法只能说"几件事"，平铺的根原样留着。）

## 二、形状（两条硬约束）

1. **id 一律字符串，容器一律字典**：`nodes` 是 `{"n1":{…}}`，
   `membership` 是 `{"21":["n5","n9"]}`。
   换成数组下标/裸标识符后 **JSON 直接解析失败**（实测 785 字符的输出里
   标识符没加引号），结构轴从 3/3 掉到 0/3。
2. **值一律是列表**，哪怕只有一个落点——"多归属"在数据形状上必须**处处合法**，
   否则模型会把它当成例外情况。
3. **存最具体落点**（`mostSpecific()`）：去掉"被同一回合里另一个落点包含"的祖先。
   中间层的路径本来就写在节点的 `parents` 里，存进落点不携带新信息；
   存最小集合后，三次运行之间的**层级风格方差**（根收 3 / 21 / 3 行）从数据里消失。
   要显示整条链时用 `closeUnderAncestors()` 展开——实测两种取法在
   travel-run3 的 11 个任务节点上**逐节点等价**（`research/closure-explained.md`）。

4. **根的数量按语义划分，不设阈值**（使用者裁定 2026-10-09：*"不应该强制限定数量，
   应该按任务领域的语义划分，同时根的拆分也表明了会话实际的任务演化分歧了"*）。
   所以流水线**不设数量闸门、不判失败**：先报告有几条非插话的线、各自从第几回合开始
   （`rootSummary()` 的 `forks`），再由**第 4 段那次语义裁定**决定要不要归并。
   多根是一条**信息**——这场会话的任务演化分叉了——面板可以据此说
   "任务在第 #83、#99 回合分叉出两条线"。
   （`ensureProjectRoot()` 仍保留为可选的纯函数，给"硬压成一个项目视图"那种展示模式用，
   默认路径不调用。）

## 四、四条不许改的措辞（都有配对实测）

1. **"闲聊"那句必须跟"不算推进"同句、且正着写。** 实测：
   - 同句正着写（`…不算推进**；闲聊若有自己的节点也算一个落点；`）→ `#21` **3/3**；
   - 写成"闲聊不算推进" → **1/3**；
   - **拆成两个 bullet**（负面一条、正面一条）→ 也掉回 **1 处落点**。
     我固化时拆过一次，是 `research/dag-label-sheet-2026-10-09.md` 里 #21 只有一处的原因。
   ⇒ 负面清单会**连带压掉正在被要求的那件事**；正面那半句必须紧跟在负面之后。
2. **第二段不要给 ops 词汇表。** 给了就退化成"一个回合一个落点"。
3. **"父节点是纯容器"这句保持原样。** 换成"父子都要挂"后
   `sudo 合并` 从 3/3 掉到 1/3、2/3，而父子双命中**并没有因此出现**（仍 0/4）。
4. **id 用字符串、值用列表**（见第二节）。

## 五、已知仍错（**不要**靠调措辞去修）

**a. `sudo` 那个节点合并了，但名字还是"原因"式。**
判据只查"只有一个 sudo 节点且 #23/#24 都挂它"（3/3 通过），
所以 `sudo 两次原因` 这种命名**照样算通过**——而使用者的真值要的是
`sudo 处理`（把节点从"问题"改成"正在做的事"，见
`research/dag-labels-2026-10-09.md`）。这是判据的盲区，不是模型的失败。
